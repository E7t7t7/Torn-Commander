LEVELING — v0.6.64

DIRECT BALDR LOADING
Choose Baldr's List 1/2/3, Extra List 1/2/3, DOMINO or All lists, then Load Baldr's list. Commander downloads https://raw.githubusercontent.com/OranWeb/tc-baldrs-levelling-list/master/data.json without any Torn API key. It validates the schema and IDs, preserves group/source order, removes duplicates and excludes the current player when identified. Lists are replaced only after the entire selected import validates; failures retain the existing queue. Source and load time are displayed. Imported levels/stats are historical references, not fresh spies or current availability. The initial verified source contains 383 entries and 382 unique IDs across seven lists; this may change upstream. OranWeb's readme permits usage/sharing. Source: https://github.com/OranWeb/tc-baldrs-levelling-list

AUTOMATIC LEVELING
1. Stop this profile's Loss Desk worker. Import/load targets. If a manual fight is pending, check its result or skip it before replacing the list.
2. Equip the desired primary/secondary/melee fighting weapon in Torn and select that slot in Leveling. Primary/secondary need ammunition. The bot pauses if the selected slot cannot be verified or is unavailable; it does not reload or switch equipment. Pillow is rejected in leveling mode.
3. Choose an attack interval (500–5000 ms), energy reserve, session attack limit (0 means no limit), and desired life target (25/50/75/100%). Full life is the default.
4. To enable healing, tick Allow automatic personal medical use for leveling and save. The account's Smart Medical optimizer must be enabled, and item permissions/reserves/bonuses remain enforced. No drugs, blood bags or faction-armory supplies are used by this planner. With healing disabled, it pauses with a recommendation when recovery is needed.
5. Start automatic leveling opens an embedded worker, scans personal Medical stocks, verifies account identity and recovery, and claims one target at a time. Current status and energy are checked through the existing paced Torn API integration. Unavailable entries are skipped for this pass, including an explicit unavailability message seen after opening the attack page.
6. The worker joins, repeatedly uses the selected equipped weapon, chooses a single verified Leave control after winning, then waits for the official outgoing attack log. It matches account, target, start time and unseen attack ID before crediting a Leave win. Other results count separately and stop continuation after recovery for review. Cached receipts are retried without another attack. No exact XP estimate is manufactured.
7. Between fights the worker optimizes both hospital exit AND the chosen life target with permitted Small FAK/FAK/Morphine. It authorizes one item, verifies one decrement and expected cooldown/life changes, then replans. Cached post-use responses get bounded retries without consuming another item. SFAK/FAK/Morphine restore base 5/10/15% life and remove base 20/40/70 hospital minutes; cooldown costs are 10/15/20 minutes. Bonuses increase healing, not cooldown cost. Final-item overshoot follows existing medical eligibility rules. Full healing can consume substantial cooldown.
8. Pause/Resume retains the same pending fight or medicine operation. Stop ends the worker and must be used before changing settings or replacing the queue. Native app/browser restart requires explicit resume/start. Use Show fight window to inspect controls. Session medical counts and cooldown are shown separately from loss-contract accounting.
9. Energy reserves, attack limits or exhausted target lists stop new attacks. New pass resets visited targets without clearing totals or limits. Optional cooldown auto-resume follows the saved Smart Medical setting; unknown supplies/state always pause.

MANUAL TOOLS
Check next, Open checked target, Check fight result and personal inventory reading remain available while automatic leveling is stopped. Read visible medical counts reads only the active manually opened Medical page after verifying its account; quantities can also be entered as estimates. These manual estimates are not substituted for fresh worker stock checks in automatic mode.

LIMITATIONS / VERIFICATION
API responses may be cached; restricted keys may lack attack-log/perk access. Target lists and FF estimates cannot guarantee wins. The runtime pauses on ambiguous/changed controls, verification screens or uncertain item consumption, with no CAPTCHA bypass or drug fallback. Current game rules: https://www.torn.com/rules.php. Development tests use fixtures; no real account fights/items are consumed in automated validation.

Medical references: https://wiki.torn.com/wiki/Small_First_Aid_Kit ; https://wiki.torn.com/wiki/First_Aid_Kit ; https://wiki.torn.com/wiki/Morphine
API fields verified against https://www.torn.com/swagger/openapi.json: user/profile, user/{id}/profile, user/bars, user/cooldowns, user/perks and user/attacks. Attack receipt access requires a Limited/Full key.
